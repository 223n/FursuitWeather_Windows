# 掲示モード

会場の専用の端末に置き、来場者へ判定を掲げ続けるための全画面のスライドです。
Mac版の会場表示と、本体のWebの掲示の画面（`/display`）に倣います。

## 決めたこと

2026年9月11日に、利用者と次のとおり決めました。

| 項目 | 決めたこと | 理由 |
| ---- | ---- | ---- |
| 使う場面 | 会場の専用の端末。無人で、来場者に見せる | 利用者の回答 |
| 作り方 | XAMLで自前に書く | 利用者の選択。Webを埋め込む案と、Edgeのキオスクで開く案を比べたうえで選んだ |
| スライド | いまの判定、この後の予報、3日間の天気、全国の天気。もしものときは条件つき | Webの掲示の画面と揃える |
| 地点 | 小窓と共有する。地名や郵便番号で検索して選ぶ | 専用の端末では、アプリの地点がそのまま会場になる |
| 掲示中の通知 | すべて出さない | 掲示そのものが伝える役を担い、トーストは来場者の見る画面に重なる |
| 掲示中の自動インストール | 保留し、掲示を終えたときに入れる | 掲示を途切れさせない |
| 操作 | Webと同じ。ただし一時停止は自動で解く | 自動で送る表示を止める手段を持つ。無人の端末で止まったままにしない |
| モニターが外れたとき | 残ったモニターへ移して続け、注意を出す | 無人の端末で、一瞬抜けただけで止まったままにしない |
| 起動したとき | 「起動したら掲示で始める」を設定で選べる。既定は切る | 停電や再起動のあとに、人の手を借りずに掲示へ戻す |

Webを埋め込む案（WebView2）を退けた記録は[技術選定](stack.md)にありますが、あれは透過の小窓に載せる場合の話です。
掲示の窓は不透明なので、その制約には当たりません。
今回は利用者がXAMLを選んだため、この文書はその前提で書きます。

## 本体とMac版との関係

Mac版の会場表示は、本体のWebの掲示の画面を手本にしてSwiftで書き直したものです（Mac版の`docs/design.md`）。
Windows版も同じく書き直しますが、**表示の細部はWebに倣います。**
同じ会場でWebの画面やスマホと並べたときに、食い違わないようにするためです。

| 項目 | 倣う先 | 中身 |
| ---- | ---- | ---- |
| 巡回の方式 | Web | スライドごとに期限を持つ。もしものときが出入りしても、位置が飛ばない |
| いまの時間の行が欠けたとき | Web | 当日の直近の未来の行を出し、時刻を添える |
| 暑さ指数 | Web | 素の値と、着衣補正後の値を並べる |
| 公式の発表 | Web | 常に見える帯にし、「環境省発表」と県名を必ず出す |
| 低温の見分け方 | Web | レベルの名前が`cold`で始まるものだけを低温とする |
| 鮮度 | Web | 「HH:MM時点」を常に出す。60分で古さを、未来へ5分のずれで時計の狂いを知らせる |
| 出典 | Web | 画面の下に常に出す |
| 画面の合わせ方 | Mac | 1280×720で組み、画面へ拡大する |
| この後の予報の数え方 | Mac | 時刻の値で突き合わせる。Webは配列の位置で数えている |

Mac版の実装には、鮮度の注意が一度も出ない疑いと、補正後の値を「暑さ指数」と題している点があります。
どちらも写しません。

## 写さないもの

| 写さないもの | 理由 | 代わり |
| ---- | ---- | ---- |
| 推定の警戒帯（暑さ指数33以上で出す帯） | クライアントが閾値で判定することになる。本体のAPIはこの判定を返していない | 本体にフラグを返してもらう案を、別に相談する |
| 洗濯のレベルから配色を引く表 | 判定の`grade`以外から配色を引く表になる | 洗濯は文字だけを出す |
| 公式の発表の帯に添える助言の文 | Webのクライアントが持っている文で、APIは返さない | 助言はいまの判定の`advice`が担う |
| 掲示の中の設定パネル、流れるお知らせ、都市の選択 | Webの端末ごとの設定 | 設定はアプリの設定画面に集める。全国の都市はAPIが返すものだけを出す |
| 本日の予定（Mac版だけの機能） | 範囲の外とした | 必要になったら別に扱う |

**推定の警戒帯を出さないため、同じ会場のWebの画面より、安全側の情報が1つ少なくなります。**
Webはこの帯を「安全に直結するため先頭で表示し続ける」ものとしています（本体の`docs/display.md`）。
本体がフラグを返すようになれば、描くだけで揃えられます。

## スライド

順は`いまの判定 → この後の予報 → 3日間の天気 → 全国の天気`で固定します。
もしものときは、条件を満たすあいだだけ最後に加えます。

| スライド | 秒 | 出すもの | データが無いとき |
| ---- | ---- | ---- | ---- |
| いまの判定 | 15 | 天気、「N時の予報」、気温、`advice`、補助の数値（暑さ指数の素の値と補正後の値、体感温度、湿度、風速、当日の最高と最低） | 「いまの時間の予報がありません」 |
| この後の予報 | 20 | いまの時間を含む6時間。時刻、天気、気温、判定のバッジ。日付が変われば「翌」を添える | 「この後の時間の予報がありません」 |
| 3日間の天気 | 15 | 今日から日付で選んだ3日。天気、最高と最低、日中で最も厳しい屋外判定、洗濯の文字 | 「日別の予報がありません」 |
| 全国の天気 | 20 | 全国の天気のAPIが返した都市。都市名、天気、最高気温、日中で最も厳しい屋外判定 | 0件なら「取得できていません」。欠けがあれば件数を添える |
| もしものとき | 20 | 5つの手順と、詳しい手順のURL | 条件を満たすときだけ出す |

もしものときを加える条件は、いまの屋外判定の`grade`が3以上で、低温ではないことです。
[通知の設計](notifications.md)が本体から踏襲すると決めた条件と同じです。
低温の`grade 4`に熱中症の手順を出すのは誤誘導になります。

5つの手順の文は、本体の`public/display.js`の`renderEmergencySlide`から写します。
写したことと写し元をコードに書き、ずれたら直せるようにします。
本体の`/emergency`のページは別の文なので、同期の相手にしません。

## 共通の帯

どのスライドでも、上と下に同じ帯を出します。

上の帯に出すもの。

1. 地点名。既定の地点のままなら「地点が設定されていません」と添える
1. いまの屋外判定のバッジと「連続N分まで」。0分なら「着用中止」
1. この先3時間で、いまより厳しい時間があれば、その時刻と判定
1. 公式の発表があれば「環境省発表: 県名に種別」。対象日を過ぎた発表は出さない
1. 注意。1件だけで済ませず、すべて積む。通信の失敗、古さ、時計のずれ、モニターの移動、既定の地点が当たる

3つ目は、掲示のあいだトーストを止める代わりです。
選び方は、トーストの判定（T1）と同じ`ChangeDetector.SelectTarget`をそのまま使います。
同じ規則を2か所に書かないためです。

下の帯には「HH:MM時点」と出典を出します。
出典の文はレスポンスの`attribution`から取ります。

## 切り替え

- 各スライドに期限を持たせ、1秒ごとに期限を見て進めます。スリープから戻っても、次の見直しで追いつきます
- もしものときが出入りしても、いま出しているスライドを保ちます
- 手元のデータで1分ごとに描き直します。予報が届いたときの知らせは、取得に成功したときにしか来ないためです
- 切り替えは0.3秒で消してから0.3秒で出します。Windowsのアニメーションを切っている端末では、効果なしで差し替えます

## 画面の合わせ方

- 1280×720で組み、`Viewbox`で画面へ拡大します。縦横の比が違えば中央に置き、余りを塗ります
- 文字の大きさは、この座標の上で決めます。目安はMac版と同じで、気温が120、天気名が76、地点名が46、本文が30前後、注意が20です
- 焼き付き対策として、3分ごとに1pxずつ4か所を巡ります
- 縦置きの組み替えは、最初の版では作りません

## 窓の構成

**小窓とは別の、不透明な窓を足します。**
小窓を全画面へ引き伸ばさない理由は3つです。

1. 透過の窓はClearTypeが効かず、描画の費用も測っていません
1. 小窓はキー入力を受け取らない作りで、Escもホットキー以外のキーも届きません
1. 小窓にはクリックスルーのガードが付いています。全画面で入力を素通しすると、操作する手段が無くなります

小窓はアプリの主の窓のままにします。
掲示の窓を主にすると、掲示を閉じたときにアプリが終わるためです。

- 掲示のあいだ、小窓は隠します。小窓を出す経路はいくつもあるため、「掲示中は出さない」を1か所の条件にまとめます
- 取得、通知、更新、トレイは今のまま小窓の側が持ちます。掲示の窓は受け取って描くだけにします
- 受け取ったデータは、必ずUIのスレッドへ寄せてから描きます。回線の回復から直に来る知らせが、別のスレッドで起きうるためです
- 地点を変えたら、掲示も「取得中」へ戻します。前の地点の判定を掲げ続けないためです
- 窓はモニターの矩形へ、物理ピクセルのまま置きます。`WindowState=Maximized`は、タスクバーの扱いを確かめていないため使いません
- 最前面にするかは、タスクバーやダイアログとの重なりを実機で測ってから決めます

## 操作と抜け方

- マウスを動かすと、下に「一時停止」「次へ」「掲示を終える」の帯とカーソルが出ます。3秒動かさなければ、どちらも隠します
- 「次へ」、左右の矢印キー、画面のクリックやタップで、手動で送れます。送ったスライドの秒数が過ぎれば、自動送りへ戻ります
- **一時停止は5分で自動的に解きます。** Webは「再開」を押すまで止まったままですが、無人の端末では止まったままになりうるためです。止めているあいだも、上の帯は出し続けます
- Escキーで掲示を終えます

抜ける経路は3つ用意します。
小窓のクリックスルーで、経路が1つしか無くて詰まった教訓によります（[構成](architecture.md)）。

1. 掲示の窓の中の、Escキーと「掲示を終える」
1. トレイのメニューの「掲示を終える」
1. 掲示を終えるグローバルホットキー。組み合わせは実装で決め、登録できなかったら注意を出す

全画面の窓がタスクバーを覆うと、2つ目に手が届かなくなります。
そのため3つ目も必ず置きます。

## モニター

- 掲示を出すモニターは、設定画面で選びます。指定が無ければ主モニターへ出します
- 選んだモニターを見分ける値は、再起動や抜き差しのあとも同じであるものを使います。何が使えるかは実機で確かめます
- 開いているあいだに掲示先が外れたら、残ったモニターへ移して続け、注意を出します。戻ってきたら元へ戻します

## スリープ

掲示のあいだ、`SetThreadExecutionState`で画面と端末のスリープを抑えます。
終えたら元へ戻します。

**スクリーンセーバーは止められません。**
この関数はスクリーンセーバーの起動を止めない、とMicrosoftの文書に明記されています。
画面のロックのポリシーも同じです。
スクリーンセーバーとロックは、設置の手順で切ってもらいます。

## 通知

**掲示のあいだは、トーストをすべて出しません。**
判定が危険に上がったとき（T1）と公式の発表（T3）も含みます。
[通知の設計](notifications.md)の「T1とT3は抑制の対象外」の、唯一の例外です。

- 通知の状態は進めます。掲示が伝えたものとみなし、掲示を終えたときにまとめて出しません
- 朝の便りも出しません
- 更新の知らせも出しません
- 「起動したら掲示で始める」のときは、起動したときの更新の成否のトーストも出さず、掲示の注意へ回します

## 更新

- 掲示のあいだは、自動のインストールを保留します。更新のゲートに「掲示中」という理由を足します
- 取得は止めません
- 掲示を終えたら、1分ごとの見直しが拾います
- 利用者がトレイの「更新をインストール」を押したときは入れます。押した人がその場にいるためです

全画面の窓を「割り込んではいけない状態」と見なすかは、Windowsの判断（`SHQueryUserNotificationState`）に任せません。
掲示中かどうかをアプリ自身が知っているため、それをゲートに渡します。

## 地点

- 設定画面に検索の欄を置きます。地名か郵便番号で`/api/geocode`を呼び、候補を「名前（都道府県）」で並べます
- 候補を選ぶと、緯度、経度、表示名が入ります。送る座標は、これまでどおり小数2桁へ丸めます
- 郵便番号で引いた座標は、市区町村の代表点になることがあります。候補の近くに添えて知らせます
- 既定の地点のままなら、掲示の上の帯に注意を出します。会場の端末で、よその判定を黙って掲げないためです

## 起動したら掲示で始める

- 設定画面の項目にします。既定は切ります
- 入れていると、起動の最後に掲示へ入ります。自動起動と組み合わせれば、停電や再起動のあとも掲示へ戻ります
- 起動の引数には頼りません。自動起動、更新のあとの起動し直し、インストールの完了の画面からの起動は、どれも引数を渡さないためです

## 使うAPI

| API | いま | 掲示での用途 | 取り直し |
| ---- | ---- | ---- | ---- |
| `GET /api/forecast` | 使っている | いまの判定、この後の予報、3日間 | 11分ごと（今までどおり） |
| `GET /api/alert` | 使っている | 公式の発表の帯 | 31分ごと（今までどおり） |
| `GET /api/national` | 足す | 全国の天気 | 31分ごと |
| `GET /api/geocode?q=` | 足す | 設定画面での地点の検索 | 押したときだけ |

全国の天気は、取れなかった都市を含めずに返します。
件数が減っていれば、欠けていることを画面に出します。
`generatedAt`と`date`で古さを見ます。
WebとMac版は全国の古さを出していませんが、掲示し続ける端末では要ります。

## 判定を複製しない制約との照合

クライアントに残してよいのは、[APIの利用](api-client.md)の4項目だけです。
掲示では、次のとおりその範囲に収めます。

| 掲示でやること | どの項目に当たるか |
| ---- | ---- |
| いまの行、この後の6時間、日付で日を選ぶ | 1つ目（いまの時間帯にあたる行を選ぶ）を広げて読む。APIの利用に書き足す |
| 鮮度、時計のずれ、取り直し | 2つ目と3つ目 |
| `grade`と`cold`の接頭辞から配色と記号を引く | 4つ目 |
| この先3時間で最も厳しい時間 | 通知の規則（T1）と同じ関数を使う |
| もしものときを加える条件 | 通知の設計が本体から踏襲すると決めた条件 |
| 公式の発表の対象日を過ぎたら出さない | 日付の比較で、判定ではない |

推定の警戒帯と、洗濯の配色の表は、この範囲の外なので写しません（上の「写さないもの」）。

## 実装の段階

1. **Core**: 掲示の規則（巡回、行と日の選び方、帯の文、鮮度、焼き付きのずらし、配色の区分、モニターの選び方）と、そのテスト。全国の天気と地点の検索の取得。更新のゲートの「掲示中」
1. **掲示の窓**: スライドと帯と切り替え。操作と抜け方。スリープの抑止、小窓を隠すこと、通知と更新の抑制、モニターの移動
1. **設定**: 地点の検索、掲示先のモニター、起動したら掲示で始める
1. **実機での確認**: 下の「確かめていないこと」を上から順に測る

規則はCoreに置き、Linuxのランナーでもテストを回します。
時刻は`JstTime`を通します。
窓の置き方、スリープの抑止、ホットキーはCoreに置けないため、実機で確かめます。

## 確かめていないこと

| 前提 | 何に効くか |
| ---- | ---- |
| 自前の全画面の窓で、`SHQueryUserNotificationState`が何を返すか | 小窓の自動の隠し方との食い違い |
| 全画面の窓がタスクバーを覆うか。ダイアログやトレイのメニューとの重なり | 最前面にするか、抜け方 |
| モニターを見分ける値が、再起動や抜き差しのあとも同じか | 掲示先の保存 |
| モニターを抜いたとき、窓がどこへ移るか | モニターの移動 |
| モニターごとに倍率が違う構成で、窓がモニターいっぱいに収まるか | 置き方。倍率の違う2枚目のモニターが要る |
| スリープの抑止が効くか（`powercfg /requests`で見る） | 無人の運用 |
| `Viewbox`で拡大した文字が、遠くから読めるか | 文字の大きさ |

## まだ扱っていないこと

- 無人の端末での異常終了。いまはクラッシュの画面がOKを待ったまま止まります
- 何日も動かし続けたときのメモリの増え方
- リハーサル用のデモの表示
- 縦置きのモニター
- 本日の予定

## 本体への提案（範囲の外）

次の2つは本体のリポジトリの変更になるため、Windows版が動いてから別に相談します。

- 推定の警戒帯を、判定の結果としてAPIが返すこと
- もしものときの5つの手順を、1か所に置いて配ること。いまは本体のWeb、Mac版、Windows版の3か所に写しがあり、ずれても機械で気付けません
